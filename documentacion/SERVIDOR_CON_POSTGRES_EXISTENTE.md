# SERVIDOR QUE YA TIENE PostgreSQL 12 (con otra aplicación) — cómo proceder

> **Situación:** la PC servidor de la empresa **ya tiene PostgreSQL 12 trabajando con otra
> aplicación**. Nuestro sistema **no lo va a tocar**: se instala aparte, en **otro puerto**.

## 1. ¿La versión 12 es un problema? — **NO**

El sistema funciona en PostgreSQL **12** (de hecho necesita **10 o superior**). Revisado el SQL que
usa el programa:

| Lo que usa el programa | Necesita | ¿Está en la 12? |
| --- | --- | --- |
| `GENERATED BY DEFAULT AS IDENTITY` (los `id` de todas las tablas) | PostgreSQL **10+** | ✅ Sí |
| `ON CONFLICT … DO NOTHING / DO UPDATE` | 9.5+ | ✅ |
| `RETURNING`, `STRING_AGG`, `to_char(now(), …)` | 9.0+ | ✅ |
| `TRUNCATE … RESTART IDENTITY CASCADE`, `pg_get_serial_sequence`, `setval` | 8.4+ | ✅ |
| `information_schema`, `substr`, `BYTEA` (las facturas guardadas) | desde siempre | ✅ |
| Conector `psycopg2` (viene dentro del `.exe`) | 9.6+ | ✅ |

⚠️ **Lo que sí importa** (y por eso hay que decidir con cuidado):

- **El PUERTO.** Su instancia usa el **5432**. Si nuestra base se instala en el mismo puerto, chocan y
  **se cae su aplicación**. → Nosotros usamos **otro puerto (5433)**.
- **No mezclar carpetas de datos.** Nunca apuntar una versión nueva a la carpeta `data` de la 12.
- **La 12 está fuera de soporte** (desde fines de 2024, sin parches de seguridad). Es un tema de *su*
  servidor, no del programa — y **no es algo que debamos cambiar nosotros**: actualizar su 12
  rompería su aplicación.

## 2. Las 3 reglas de oro (para no dañar nada)

1. **No tocar** su `postgresql.conf`, su `pg_hba.conf`, sus bases, sus usuarios ni su carpeta `data`.
2. **No actualizar** su PostgreSQL 12 (nada de `pg_upgrade` ni instalar "encima").
3. Todo lo nuestro va **separado**: otro puerto (**5433**), otra carpeta de datos, otro servicio,
   nuestro usuario/base (`miempresa` / `viaticos`) y **nuestro propio respaldo**.

## 3. Primero: reconocer el terreno (no cambia nada, es solo mirar)

En el servidor, **PowerShell como Administrador**:

```powershell
# a) ¿Qué servicios de PostgreSQL hay y en qué estado?
Get-Service postgresql* | Format-Table Name, DisplayName, Status, StartType -AutoSize

# b) ¿Qué puertos están ocupados?  (anota cuáles aparecen)
netstat -ano | Select-String ":5432|:5433|:5434"

# c) ¿Qué instalaciones/versiones hay en el disco?
Get-ChildItem "C:\Program Files\PostgreSQL" -ErrorAction SilentlyContinue | Select-Object Name

# d) Windows, memoria y espacio libre (para saber si entra la 18)
(Get-CimInstance Win32_OperatingSystem).Caption
[math]::Round((Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory / 1GB, 1)
Get-PSDrive C | Select-Object @{n='LibreGB'; e={[math]::Round($_.Free/1GB,1)}}
```

Con eso confirmas: **su base en 5432** y que **5433 está libre para nosotros**.

## 4. Las dos formas de proceder

| | **Opción A (recomendada): instancia propia en 5433** | **Opción B: usar su instancia 12 (base nueva)** |
| --- | --- | --- |
| Qué se instala | PostgreSQL 18 (o 17) en esta PC | **Nada** |
| Puerto | **5433** (ellos siguen en 5432) | 5432 (el de ellos) |
| ¿Toca algo de ellos? | **No** (todo separado) | Sí: su `pg_hba.conf` + se crea rol y base dentro de su instancia |
| Si ellos reinician o actualizan su base | **Nosotros seguimos** | Nuestro sistema también se cae |
| Soporte y seguridad | Versión soportada | Versión **EOL** (sin parches) |
| Permisos necesarios | Solo ser administrador de la PC | Autorización del administrador de su PostgreSQL |
| Respaldos | Los nuestros (`pg_dump -p 5433`) | Se mezclan con los de ellos |

## 5. Opción A paso a paso (instancia NUESTRA, puerto 5433) — recomendada

**A.1 Instalar** PostgreSQL 18 (instalador de `postgresql.org` / EDB):
- **Port: `5433`** ← el cambio clave (no 5432, que es el de ellos).
- Data directory: `C:\Program Files\PostgreSQL\18\data` (el instalador **no** toca la carpeta de la 12).
- Clave del superusuario `postgres`: anótala.
- **No pide reiniciar la PC**; al terminar queda el servicio `postgresql-x64-18` en *Automático*.

**A.2 Comprobar que conviven las dos bases:**
```powershell
Get-Service postgresql* | Format-Table Name, Status, StartType -AutoSize
netstat -ano | Select-String ":5432|:5433"
#   5432 = la base de ellos (NO tocar)   ·   5433 = la nuestra
```

**A.3 Crear nuestro usuario y nuestra base** (ojo: `psql` de la 18 y **`-p 5433`**):
```powershell
$env:PGPASSWORD = "la-clave-de-postgres-18"
$psql = "C:\Program Files\PostgreSQL\18\bin\psql.exe"

& $psql -U postgres -p 5433 -c "CREATE USER miempresa WITH PASSWORD 'miempresa';"
& $psql -U postgres -p 5433 -c "CREATE DATABASE viaticos OWNER miempresa;"
& $psql -U postgres -p 5433 -c "\l" | Select-String "viaticos"
```

**A.4 Configurar SOLO la carpeta de la 18:**
```powershell
notepad "C:\Program Files\PostgreSQL\18\data\postgresql.conf"
#   listen_addresses = '*'
#   port = 5433
#   timezone = 'America/Guayaquil'

notepad "C:\Program Files\PostgreSQL\18\data\pg_hba.conf"
#   al final:   host    all    all    192.168.0.0/16    scram-sha-256

Restart-Service postgresql-x64-18
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -p 5433 -c "show port; show listen_addresses; show timezone;"
#   Debe decir: 5433 | * | America/Guayaquil
```

**A.5 Firewall: abrir el 5433** (el 5432 es de ellos):
```powershell
New-NetFirewallRule -DisplayName "Viaticos PostgreSQL 5433" -Direction Inbound -Protocol TCP -LocalPort 5433 -Action Allow -Profile Any
```

**A.6 Verificar desde otra PC:**
```powershell
Test-NetConnection -ComputerName <IP del servidor> -Port 5433      # True
```

**A.7 Respaldo diario propio** (el `.bat` con **`-p 5433`**):
```bat
"C:\Program Files\PostgreSQL\18\bin\pg_dump.exe" -U miempresa -h 127.0.0.1 -p 5433 -d viaticos -f "respaldos_base\viaticos_%FECHA%.sql"
```
+ la tarea `schtasks /Create … /SC DAILY /ST 20:00 /RL HIGHEST /F` como en el Plan C.

## 6. Opción B paso a paso (base nueva dentro de su PostgreSQL 12)

1. **Pide autorización** al responsable de ese PostgreSQL (es su servidor y su instancia).
2. Que se cree el rol y la base **en su instancia** (puerto 5432):
```powershell
& "C:\Program Files\PostgreSQL\12\bin\psql.exe" -U postgres -p 5432 -c "CREATE USER miempresa WITH PASSWORD 'miempresa';"
& "C:\Program Files\PostgreSQL\12\bin\psql.exe" -U postgres -p 5432 -c "CREATE DATABASE viaticos OWNER miempresa;"
```
3. Que en **su** `pg_hba.conf` agreguen la línea de la red y recarguen (sin reiniciar el servicio):
```
host    all    all    192.168.0.0/16    scram-sha-256
```
```powershell
& "C:\Program Files\PostgreSQL\12\bin\psql.exe" -U postgres -p 5432 -c "select pg_reload_conf();"
```
4. El programa se configura con **puerto 5432** (el de ellos).
5. Respaldos: que su respaldo diario incluya la base `viaticos`, o hacemos el nuestro
   (`pg_dump … -p 5432 -d viaticos`).

> ⚠️ En la 12 el `password_encryption` puede estar en `md5`: si al crear el usuario queda con md5 **no
> hay problema**, `psycopg2` lo soporta igual.
>
> ⚠️ Riesgos de la Opción B: si ellos reinician o actualizan su instancia, **nuestro sistema también se
> cae**; y nuestros datos quedarían en una versión sin parches de seguridad.

## 7. Lo que hay que cambiar en el programa (solo si el puerto es 5433)

En `sistema_viaticos_miempresa\configuracion.py`, dentro de `DEFECTO` → `postgres`:
```python
"puerto": 5433,
```
y lo mismo en los `config.json` (el del programa y el que está junto al `.exe`). Después:
```
EMPAQUETAR_EXE_SERVIDOR.bat 192.168.1.123 5433
```
para que el `.exe` salga ya con ese puerto.

👉 **Dime la IP del servidor, el puerto que usaremos (5433 o 5432) y la clave**, y hago esos cambios y
te dejo el `.exe` reempaquetado y probado.

## 9. ¿Qué pasa si instalo una SEGUNDA versión de PostgreSQL en el servidor?

**Nada malo, si se respeta el puerto.** Las dos quedan **conviviendo**, cada una por su lado:

| | La de ellos (12) | La nuestra (18) |
| --- | --- | --- |
| Carpeta del programa | `C:\Program Files\PostgreSQL\12` | `C:\Program Files\PostgreSQL\18` |
| Datos | `…\12\data` | `…\18\data` |
| Servicio de Windows | `postgresql-x64-12` | `postgresql-x64-18` |
| Puerto | `5432` | **`5433`** |
| Usuario / base | los suyos | `miempresa` / `viaticos` |
| Configuración | su `postgresql.conf` / `pg_hba.conf` | los nuestros |

- El instalador de la 18 **no toca nada** de la 12: su carpeta, sus datos, su servicio y su aplicación
  siguen **exactamente igual**.
- Las dos arrancan solas (servicio en *Automático*). Ocupan unos cientos de MB de disco y muy poca
  memoria (nuestra base es chica: 5 PC).
- Se pueden desinstalar por separado: si algún día se quita la 18, la 12 queda intacta (y al revés).

### Los 2 únicos cuidados

1. **El puerto.** El instalador de la 18 pone **5432** por defecto: hay que **cambiarlo a 5433**. Si se
   deja en 5432, el servicio de **la 18 no arrancará** (`Address already in use`); a la 12 **no le pasa
   nada**, pero hay que corregirlo:
   ```powershell
   notepad "C:\Program Files\PostgreSQL\18\data\postgresql.conf"    # port = 5433
   Restart-Service postgresql-x64-18
   ```
2. **Nunca** apuntar la 18 a la carpeta de datos de la 12 (`…\12\data`): una versión nueva **no puede
   abrir** datos de una versión anterior (y forzarlo con `pg_upgrade` es irreversible). Cada versión
   con **su** carpeta `data`.

### Detalle de los respaldos con dos versiones instaladas

`pg_dump` no puede sacar respaldo de un servidor **más nuevo** que él. El script
`respaldar_base_nativo.bat` busca la carpeta más alta en `C:\Program Files\PostgreSQL\*`, así que con
12 y 18 usará la **18** (que sí puede respaldar a las dos). Aun así, pruébalo después de instalar:

```powershell
servidor\respaldar_base_nativo.bat miempresa 5433
```

Si saliera `server version mismatch`, escribe la ruta completa del `pg_dump` de la 18 dentro del `.bat`.

### Y si prefieres **no instalar nada** → Opción 2

Usar **su instancia 12** creando ahí el rol `miempresa` y la base `viaticos` (ver sección 6). Es
válida (la 12 cumple lo que el programa necesita) y no hay que instalar ni abrir puertos nuevos; el
precio es depender de su instancia (si ellos la reinician o actualizan, nuestro sistema se cae) y de
una versión sin soporte de seguridad.

## 10. ¿Y si uso OTRO puerto, por ejemplo 2345?

**Sirve cualquier puerto libre.** PostgreSQL no exige el 5432: el 5432 es solo la costumbre. Lo único
que hay que hacer es **cambiar el puerto en todos los lugares donde se escribe** y abrir ese puerto en
el firewall.

| Dónde | Qué poner (ejemplo con `2345`) |
| --- | --- |
| `postgresql.conf` (carpeta `data` de la 18) | `port = 2345` |
| `pg_hba.conf` | **no cambia** (ahí no se escribe el puerto) |
| Firewall del servidor | regla TCP de entrada `-LocalPort 2345` |
| Empaquetar el `.exe` | `EMPAQUETAR_EXE_SERVIDOR.bat <IP> 2345` |
| Cada PC | puerto `2345` — y **borrar** cualquier `config.json` viejo que haya junto al `.exe` |
| Respaldos | `servidor\respaldar_base_nativo.bat miempresa 2345` |
| Probar | `servidor\PROBAR_SERVIDOR.bat <IP> 2345` · `psql -U postgres -p 2345 -c "select 1;"` |

**Antes de elegirlo, comprobar que esté libre** (y que Windows no lo tenga reservado):

```powershell
netstat -ano | Select-String ":2345"                     # no debe salir nada
netsh int ipv4 show excludedportrange protocol=tcp       # que 2345 no caiga dentro de un rango excluido
```

**Ventajas:** ninguna técnica (un puerto raro **no** es "más seguro": un escaneo lo encuentra igual).
**Desventajas:** sorprende a quien lo vea (todo el mundo espera 5432), hay que anotarlo bien en **todos**
los lados, algunos firewall corporativos solo dejan salir a puertos "conocidos", y si algún día se
cambia hay que **reempaquetar el `.exe`** y tocar cada PC.

**Dos cosas tranquilizadoras:**
- El 2345 no choca con los puertos temporales de Windows (esos van del **49152 al 65535**), ni necesita
  permisos especiales (solo los puertos **menores de 1024** los piden).
- El puerto no aparece en `pg_hba.conf`, así que **ese archivo no se toca**.

**Si el servicio no arranca después de cambiar el puerto**, el motivo está en el registro:

```powershell
Get-ChildItem "C:\Program Files\PostgreSQL\18\data\log" | Sort LastWriteTime -Desc | Select -First 1
# y mirar el final de ese archivo (buscar "address already in use" o "could not bind")
```

**Recomendación:** usa **`5433`** (queda claro que es "el otro PostgreSQL de esta máquina") salvo que
ese también esté ocupado. El **2345 funciona exactamente igual**; el único precio es tenerlo bien
documentado para los que vengan después.
